rules_kconfig

rules_kconfig

Bazel rules for parsing Kconfig files and generating equivalent Bazel build settings and config.h headers.

Module extension

The primary interface is the kconfig module extension. Each kconfig.repo tag parses a Kconfig file tree and generates a repository containing:

  • A bool_flag, int_flag, or string_flag for every config symbol.
  • A cc_library target (:config) that provides config.h reflecting the active flag values.
kconfig = use_extension("@rules_kconfig//kconfig:extensions.bzl", "kconfig")
kconfig.repo(
    name = "my_kconfig",
    kconfig = "//:Kconfig",
)
use_repo(kconfig, "my_kconfig")

The tree is parsed by the Linux kernel's Kconfig parser, which a release of rules_kconfig publishes as a WebAssembly module (Bazel 9.3 or newer with --experimental_repository_ctx_execute_wasm) and as a native build per platform; no Python interpreter is needed.

Use kconfig.overrides to overlay a .config file onto an external kconfig repository via a Starlark transition:

kconfig.overrides(
    name = "my_board_config",
    kconfig = "@ext_kconfig//:ext_kconfig",
    config = "//:.config",
)
use_repo(kconfig, "my_board_config")

See the Introduction for full setup and usage instructions.

kconfig_library

load("@rules_kconfig//kconfig:defs.bzl", "kconfig_library")

kconfig_library(name, deps, srcs, env, env_labels, kconfig_version, root)

Collect Kconfig source files into a single provider for use by menuconfig and repository rules.

All source files must be real (non-generated) files. If a single source is provided, it is automatically treated as the root. When multiple sources are present, set root explicitly to indicate the top-level Kconfig entry point. Transitive sources from deps are included in the provider, as are their variables; the library's own take precedence.

The release the tree is written for (kconfig_version) and the variables its files read (env, env_labels) are properties of the tree, so they live here, and menuconfig takes them from the provider. The lib of a generated repository carries what its kconfig.repo was given.

make_variable_setting

load("@rules_kconfig//kconfig:defs.bzl", "make_variable_setting")

make_variable_setting(name, equals, expression, type)

A build setting whose value is a toolchain's "Make" variable, for settings_labels.

The variables come from the targets of the common toolchains attribute, which provide TemplateVariableInfo: Bazel's C++ toolchain (@bazel_tools//tools/cpp:current_cc_toolchain) has CC, C_COMPILER, LD, NM, OBJCOPY, STRIP and more, rules_rust's (@rules_rust//rust/toolchain:current_rust_toolchain) has RUSTC, RUSTDOC and CARGO. The value is a string as expanded, an int, or a bool that says whether the expansion equals a text:

make_variable_setting(
    name = "cc",
    expression = "$(CC)",
    toolchains = ["@bazel_tools//tools/cpp:current_cc_toolchain"],
)

make_variable_setting(
    name = "cc_is_clang",
    equals = "clang",
    expression = "$(C_COMPILER)",
    toolchains = ["@bazel_tools//tools/cpp:current_cc_toolchain"],
    type = "bool",
)

Named in settings_labels, such a target gives a CONFIG_* symbol the value of the toolchain Bazel resolved for the build, in config.h and the transitions, where the repository rule saw only the variables of env. A value that takes running the compiler (a $(cc-option,...) probe) is not a Make variable; see the documentation on env for those.

ATTRIBUTES

expressionThe text to expand, with $(NAME) references to Make variables.Stringrequired
typeThe type of the setting: string, int or bool.Stringoptional"string"

menuconfig

load("@rules_kconfig//kconfig:defs.bzl", "menuconfig")

menuconfig(name, config, kconfig)

Edit a .config interactively with mconf, the make menuconfig terminal UI.

mconf is built from the kernel's scripts/kconfig of the parser version that serves the release the tree is written for (kconfig_version of its kconfig_library), the code the kconfig repository rule reads the tree with, so what the TUI accepts and writes is what the build reads. The tree's variables (env, env_labels of the library) are set for it. The launcher is the parser's native build, kconfig_tool, which a release ships for every platform.

mconf is a curses program over POSIX, so the target is for Linux and macOS: on Windows, and on a host the release has no native build of the parser for, it is incompatible, which //... skips and bazel run reports.

Run with bazel run. The TUI reads and writes the file config names, relative to the root module's workspace, which must exist there: the launcher resolves the path on disk, and refuses one that leads outside the workspace or to no file. A repository generated from a defaults file, or kconfig.overrides over a config, has a menuconfig of its own over that file when the file is the root module's.

ATTRIBUTES

NameDescriptionTypeMandatoryDefault
nameA unique name for this target.Namerequired
configWorkspace-relative path of the .config file to read and write; an existing file of the root module's workspace.Stringrequired
kconfigThe kconfig_library of the tree: its files, release and variables.Labelrequired

kconfig_overrides_repository

load("@rules_kconfig//kconfig:defs.bzl", "kconfig_overrides_repository")

kconfig_overrides_repository(name, config, kconfig, tool, wasm_module)

Overlay .config values onto an existing kconfig repository.

Reads the manifest from the source kconfig repository to locate the Kconfig tree, then reparses it where the source repository read it, with the parser of the kconfig_version the manifest records, as kconfig_repository did, with a user-provided .config file. If the source repository was itself created with a .config, the overrides are stacked on top of those base values. The tree's $(shell,...) commands answer as they did for the source repository, from its manifest, and rendered.config is written as the source repository's was (write_invisible). Generates a defs.bzl containing a Starlark transition and wrapper rule that apply the overrides.

Values explicitly set on the command line take precedence over the overlay.

The generated defs.bzl creates the transition and rule:

ruledescription
kconfig_override_transitionA transition that applies transitions for each default in .config
with_kconfig_overridesA rule similar to alias that applies kconfig_override_transition to the target

Use with_kconfig_overrides to wrap a kconfig-dependent target:

load("@base_kconfig_override//:defs.bzl", "with_kconfig_overrides")

with_kconfig_overrides(
    name = "config",
    actual = ":consumer_of_base",
)

kconfig_repository

load("@rules_kconfig//kconfig:defs.bzl", "kconfig_repository")

kconfig_repository(name, apparent_name, defaults, env, env_labels, kconfig, kconfig_version,
                   settings_labels, settings_options, tool, wasm_module, write_invisible)

Parse a Kconfig file tree and generate a Bazel repository with build settings.

The generated repository contains a bool_flag, int_flag, or string_flag for every config symbol found in the Kconfig tree, plus a cc_library target (:config) providing a config.h header that reflects the active flag values.

The Kconfig source tree is symlinked into kconfig_srcs/ and a kconfig.manifest.json records the root file and all visited files. A repo-named symlink (e.g. @my_kconfig//:my_kconfig) points to the manifest for downstream consumers.

The Kconfig tree is parsed by the kernel's parser of the release kconfig_version names, as the WebAssembly module a release of rules_kconfig carries (Bazel 9.3 or newer with --experimental_repository_ctx_execute_wasm) or as the release's native build for the host; both generate the same repository.

Prefer using the kconfig module extension rather than calling this rule directly.
